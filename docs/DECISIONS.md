## Phase 1: Smart Care, Cleanup, Space Lens, My Activity (2026-11-11)

| # | Decision | Why |
|---|---|---|
| 24 | Windows code lives in a new `crates/win` crate (drives, memory, processes, Recycle Bin, disk walk, cleanup scan). Pure logic stays in `crates/core` (rules, safety checks, health score, Space Lens tree). | Keeps the rules and scoring testable without Windows. |
| 25 | Cleanup rules are our own declarative file, `rules/cleanup.json` (paths with `{VARIABLES}` and `*` segments, item level, age, include patterns, admin, safety, default selection, programs that lock the files). winapp2.ini is not used. | Its license (CC BY-NC-SA) is likely incompatible; our 14 rules cover the spec's list. |
| 26 | Every removal is checked twice: when scanned and again just before removal (`smd_core::safety::check_removal`): absolute drive path, no `..`, at least two folders deep, never `Windows`, `System32`, `WinSxS`, `Program Files*`, `ProgramData`, `Users`, `Recovery`, `Boot`, `EFI`, and inside the rule's own folder. Symlinks and junctions are never listed or removed. | Defense in depth; the `trash` crate resolves links before recycling, so a link must never reach it. |
| 27 | A cleanup only acts on the last scan, by id, and only on items the backend found itself; the UI sends category ids and the paths the user unticked. A used scan is discarded. | The UI can never ask the backend to delete an arbitrary path. |
| 28 | Admin-only categories (Windows temp, Windows Update downloads, Delivery Optimization, system error reports, memory dumps) are shown, measured when readable, and locked until the elevated helper (Phase 4). | Least privilege: no UAC prompt in Phase 1. |
| 29 | Recycle Bin by default, in batches of 100 through `IFileOperation` (`trash` crate: `FOF_ALLOWUNDO`, `FOF_WANTNUKEWARNING`); an item the shell skips (in use) is reported as skipped. "Delete for good" is a setting, off by default, with a warning and a confirmation dialog. | Reversible by default. Recycled junk only frees space once the bin is emptied, and the UI says so. |
| 30 | Emptying the Recycle Bin is its own category, never pre-selected, labelled "Can't be undone", and always confirmed. It runs **before** the other items are recycled. | Space is freed, and what this cleanup moves to the bin can still be restored. |
| 31 | Browser caches: only `Cache_Data`, `Code Cache`, `GPUCache` (Edge, Chrome, Brave, every profile) and Firefox `cache2`. Cookies, passwords and history are not offered at all in Phase 1. If the browser is running, the row says so and locked files are skipped. | Never touch personal browser data; the spec allows it only when ticked explicitly, which can come later. |
| 32 | Smart Care Phase 1 areas: disk health (`Get-PhysicalDisk`, no admin), free space on the system drive, memory (3 samples about 1 s apart; "sustained" = the lowest sample; critical needs commit charge > 90 % too), maintenance from uptime. Protection, startup load and app updates show "Checked from phase N" and are not scored. Battery is hidden on desktops. | Every number shown is measured; unmeasured areas never lower the score. |
| 33 | Smart Care's "Clean" button cleans only the categories ticked by default (no Recycle Bin, no admin). "Review" opens the same scan in Cleanup. | One click stays safe; anything more goes through the review list. |
| 34 | Space Lens walks with our own `rayon` walker instead of `jwalk`: on Windows `std::fs::DirEntry::metadata` reuses the `FindNextFileW` data, so no file is opened. Links/junctions/mount points are skipped; unreadable folders are counted. Each folder keeps its 40 largest files over 1 MB; the rest become one "small files" box. | Speed (all of C:, 589k files, in 62 s in a debug build) and bounded memory. |
| 35 | Sizes in Space Lens are file sizes (as Explorer's "Size"), not size on disk; hard links (WinSxS) may count twice. | Simple and matches Explorer. Size on disk and the MFT fast mode can come later. |
| 36 | Space Lens shows a squarified treemap (`d3-hierarchy`), two levels deep, plus a "largest items" list and a file-type breakdown. No sunburst for now. | The treemap reads better for "what is big"; the list gives full keyboard access. |
| 37 | Space Lens scans have their own busy flag, so Smart Care and Cleanup can run while a drive is being walked. | A 1 TB walk takes minutes; it is read-only. |
| 38 | My Activity: `activity.json` (newest 500 entries) and `undo\<id>.json` (recycled paths) in `%LOCALAPPDATA%\io.github.neverint.smd`. Undo restores from the Recycle Bin items with the same original path, deleted after the cleanup started. | Undo works across restarts; nothing leaves the PC. |
| 39 | Backend settings live in `settings.json` in the same folder: exclusions and delete mode. "Always skip" in a review list adds an exclusion. | Settings the Rust side must enforce cannot live in browser storage (decision 14). |
| 40 | Progress is streamed with Tauri channels (`on_progress`); the frontend `stream()` helper mirrors `call()` and has mocks for the browser and Playwright. | Typed, ordered progress without global events. |

## Phase 2: Performance, Applications, My Clutter (2026-11-12)

| # | Decision | Why |
|---|---|---|
| 41 | Startup items come from the HKCU/HKLM `Run` keys (64- and 32-bit) and both Startup folders. They are turned off/on only through `StartupApproved` (12-byte value: odd first byte = off), exactly like Task Manager; the Run entry is never edited or deleted. Each change is in My Activity with an undo. | Reversible and identical to what Windows does. |
| 42 | Machine-wide startup items (HKLM, common Startup folder) are listed but locked until the elevated helper (Phase 4). | Least privilege. |
| 43 | A startup item counts as "Windows" when its program's `CompanyName` contains Microsoft. Squirrel launchers (`Update.exe --processStart App.exe`, used by Discord, Slack...) are resolved to the real `app-*\App.exe`. Store-app startup tasks are not listed yet. | Honest publisher names; Store startup tasks need a different API. |
| 44 | Smart Care "Startup load": third-party items that are on, 6 or fewer good, 7-12 warning, more than 12 critical. | The spec's "few / moderate / many"; impact (CPU/disk at boot) is not measurable without admin tracing. |
| 45 | Live programs use `sysinfo`, grouped by program name like Task Manager, refreshed every 2 s only while the tab is open; the monitor is freed when you leave. No "end task" button. | Idle-RAM budget; ending processes is out of scope. |
| 46 | Scheduled tasks (outside `\Microsoft\`) and services are read-only lists, minus anything whose program is published by Microsoft (and svchost-hosted services), with buttons that open Task Scheduler and Services. | Spec: read-only plus "Open in Services". |
| 47 | Boot duration comes from Diagnostics-Performance event 100 when Windows recorded it; otherwise only the last start time is shown ("Windows didn't record how long startup took"). This PC has no such events. | Never show a guessed number. |
| 48 | Installed apps: the three `Uninstall` registry views (entries with `SystemComponent`, `ParentKeyName` or update/hotfix `ReleaseType` hidden) plus Store apps of the current user (`Get-AppxPackage`, frameworks and non-removable packages hidden). Last-used dates are not shown: Windows has no reliable source. | Matches Settings > Apps. |
| 49 | Uninstall runs each app's own uninstaller through `ShellExecuteEx` (no command shell), one app at a time, so the uninstaller can ask for admin rights itself while SMD stays non-elevated. MSI products are run as `msiexec /x {GUID}` with a validated GUID; other strings are split into program + arguments (unquoted paths with spaces resolved against the disk). Store apps use `Remove-AppxPackage` with the name passed as an environment variable. | Official uninstallers first; no string ever goes to a shell. |
| 50 | Leftovers are only looked for after the app is gone, and are strict: the install folder (ticked only if named after the app), folders named after the app (or `Publisher\App`) in AppData, LocalAppData, Programs, ProgramData and Program Files, and `HKCU\Software` keys with the same names. Generic names (Common Files, Python, Google...) and Microsoft folders are never suggested. Anything under Program Files/ProgramData is locked until Phase 4. | "Default to unchecking anything outside the app's own folders." |
| 51 | Registry leftovers are exported with `reg.exe export` to `undo\<id>\n.reg` before deletion (HKCU only); undo re-imports them. Folders go to the Recycle Bin. | Every removal reversible. |
| 52 | App updates use the official `Microsoft.WinGet.Client` PowerShell module, which is not part of Windows. The Updates tab offers to download it from the PowerShell Gallery for the current user (NuGet provider + `Install-Module -Scope CurrentUser`) only when the user clicks; nothing is downloaded otherwise. The `winget` command has no structured output, so it is not scraped. | Spec: structured objects, not screen-scraping; network only for winget, and the UI says when. |
| 53 | Package ids and Appx names are checked against strict patterns and passed to PowerShell as `SMD_*` environment variables, never pasted into a script. | Never concatenate input into commands. |
| 54 | Windows Update: pending and security counts from the last Windows check (`Microsoft.Update.Session`, offline search: fast, no download), read-only, with a button to Settings > Windows Update. Smart Care gives each update check 25 s; a slow check is skipped, never guessed. | Spec: Windows Update read-only; quick scan under 30 s. |
| 55 | My Clutter scans your known folders (Desktop, Documents, Downloads, Pictures, Music, Videos, wherever they are redirected) or a folder you pick. It never walks Windows, Program Files, ProgramData, AppData, `$Recycle.Bin`, System Volume Information or hidden+system folders. | Your own files only. |
| 56 | Large = 100 MB or more; old = 10 MB or more and not changed for a year (modification date: last-access times are often disabled on NTFS); duplicates = 1 MB or more. Lists are capped at 500 entries. | Useful defaults; configurable later. |
| 57 | Duplicates: same size, then BLAKE3 of the first and last 64 KB, then full BLAKE3. Hard links (same volume serial + file index) count as one file. In each group, at least one copy must stay: the UI disables the last unticked copy and the backend refuses a request that removes every copy. "Select all but one" keeps the copy with the shortest path. | Correct duplicates only; never lose the last copy. |
| 58 | My Clutter always moves files to the Recycle Bin, even when "Delete for good" is on for Cleanup. | These are your own files, not junk. |
| 59 | Similar images (perceptual hash) are not in Phase 2. | Optional in the spec; can come later with `image_hasher`. |

## Phase 3: Protection, Hardware Health (2026-11-12)

| # | Decision | Why |
|---|---|---|
| 60 | Defender status and threat history come from `Get-MpComputerStatus`, `Get-MpThreatDetection` and `Get-MpThreat` (no admin). Scans and signature updates use Defender's own `MpCmdRun.exe` (`-Scan -ScanType 1/2`, `-SignatureUpdate`), started directly, never through a shell. Defender decides what to do with what it finds; SMD only shows it. | Spec: Defender integration, no antivirus engine of our own. |
| 61 | Defender exposes no scan percentage, so a scan shows a running ring with the elapsed time and a Stop button (which ends `MpCmdRun`). A scan has its own slot: a full scan (an hour or more) never blocks Cleanup or Smart Care. | Honest progress; no invented percentage. |
| 62 | Protection score: Defender on and signatures under 3 days good; stale signatures warning; real-time protection off or a threat still needing attention critical. When Defender runs in passive mode (another antivirus is in charge), its switches are not held against the score. | Spec table; fair to people who use another antivirus. |
| 63 | Firewall: the three profiles from `Get-NetFirewallProfile`, read-only, with a button to Windows Security. | Showing state is enough; changing firewall rules is out of scope. |
| 64 | App permissions come from the consent store (`HKCU\...\CapabilityAccessManager\ConsentStore\{webcam,microphone,location}`). Store apps can be allowed or blocked one by one (writes `Value` = Allow/Deny, as Settings does), with an undo in My Activity. Desktop apps are listed read-only with their last use: Windows only has one switch for all desktop apps, so a per-app change would be ignored. | Honest controls: only what Windows actually honours. |
| 65 | Hardware sensors come from an optional .NET 8 helper (`sidecars/hwmon`, LibreHardwareMonitorLib 0.9.6, MPL-2.0, unmodified). It prints one JSON line every 2 s, exits when its stdin closes, and runs only while the Hardware Health page is open. Framework-dependent (about 5 MB) instead of self-contained (about 70 MB). | Spec: optional sidecar, started on demand; small installer. Needs the .NET 8 runtime; without it the page says so and shows everything else. |
| 66 | LibreHardwareMonitor 0.9.5+ no longer ships WinRing0 (flagged by Defender). Run without admin rights, it loads no kernel driver at all: GPU temperatures, power and fans, CPU and memory loads work; CPU temperature, CPU power and motherboard fans need admin and arrive with the elevated helper (Phase 4). | Least privilege; nothing flagged by antivirus. |
| 67 | Readings that only mean "not available" are hidden, never shown as 0: temperatures of 0 °C or less, and CPU power of 0 W without admin. A GPU fan at 0 RPM is kept (fans stop at idle). Only the total load per device is shown. | No fake numbers. |
| 68 | The .NET 8 SDK for building the helper is installed in `G:\Documents\Dev\.dotnet` (owner's choice, nothing on C:); NuGet packages in `G:\Documents\Dev\.nuget`. CI and the release workflow build it with `actions/setup-dotnet` (`npm run hwmon`); the build output is not committed. | Keeps C: free; reproducible builds. |
| 69 | Disk health stays Windows' `HealthStatus`. SMART wear, temperature and error counters (`Get-StorageReliabilityCounter`) need admin and come with the Phase 4 helper; the page says so and points to CrystalDiskInfo (Toolbox). | Least privilege. |
| 70 | Battery: `powercfg /batteryreport /xml` (no admin), parsed for design capacity, full-charge capacity and cycle count. The section and the Smart Care area are hidden on desktops. | Spec. |

## Phase 3b: Drive Organizer (2026-11-12)

| # | Decision | Why |
|---|---|---|
| 71 | The drive policy ships as `rules/drive-policy.json` (C: Windows only, X: big games, G: light games and documents, S: disposable; games are big from 50 GB) and is saved per PC in `%LOCALAPPDATA%\...\drive-policy.json`, editable in the Drive Organizer ("Edit drive roles"). | Spec. |
| 72 | Each rule records the volume GUID (`GetVolumeNameForVolumeMountPointW`) and the disk serial on first run. Later runs match by GUID first: if a drive comes back under another letter, its role follows it and the page says so; a different drive on the old letter gets no role; a missing drive is reported, never guessed. | Spec: identify drives by volume GUID and disk serial, not only by letter. |
| 73 | Games come from launcher manifests only: Steam (`libraryfolders.vdf` + `appmanifest_*.acf`, `SizeOnDisk`), Epic (`*.item`, `InstallSize`), GOG Galaxy (registry, folder measured) and the Xbox app (`.GamingRoot`). EA app, Ubisoft Connect and Battle.net have no stable readable install records and are not listed yet. Steam's shared redistributables (app 228980) are not games. | Spec: measure from manifests, never by guessing. |
| 74 | Audit rules: a game on the Windows or disposable drive, or a big game on the light-games drive, is "wrong drive"; a light game on the big-games drive is information only; documents, media and archives of 100 MB or more on the Windows drive (outside Windows, programs, AppData and game folders) and known tool caches of 1 GB or more in the profile are "worth moving"; anything on the disposable drive outside `Scratch` and `Quarantine` is "maybe the only copy". | Spec. Uniqueness on S: is not checked by hashing other drives (too slow); every such item is flagged. |
| 75 | Drive layout area in Smart Care: no misplaced items good; over 10 GB misplaced or the Windows drive under 25 % free warning; under 15 % free, data on the disposable drive, or an unhealthy disk critical. | Spec table. |
| 76 | Only two methods are run by the app: copy-verify (files) and cache relocation (set the tool's variable in `HKCU\Environment`, broadcast `WM_SETTINGCHANGE`, then copy-verify). Games are always guided steps in their launcher (Steam: Settings > Storage > Move; Xbox: Settings > Apps > Move; Epic and GOG: uninstall and reinstall), with a button to open the right place. Installed programs are never moved. | Spec: never copy a game folder behind a launcher's back; never move program folders. |
| 77 | Copy-verify: every file copied (`CopyFileExW`, timestamps and attributes kept) to `.smdpart`, compared by size and BLAKE3, renamed; only when all files are verified does the original go to its drive's Recycle Bin. Links are skipped and counted. A journal (`migrations\<id>.json`) is saved every 2 s and at each state change; a cancelled or crashed move resumes where it stopped (a half-written `.smdpart` is redone). | Spec: resumable, never lose data. |
| 78 | The plan is a dry run with per-step checks: target role, target free space (size + 10 %, counting the steps before it), source and target health, nothing already at the target, files in use (Restart Manager, first 1000 files), programs that must be closed (per cache), and plugged in (laptops). Only steps whose checks all pass can run, and only after a confirmation listing them. Personal files go to `<target>\From C\<original path>`, caches to `<big-games drive>\Caches\<tool>`. | Spec: preflight; transparent, reversible destinations. |
| 79 | A finished move can be undone from My Activity: the original is restored from the Recycle Bin, then the copy is recycled and the variable restored. | Reversible by default. |
| 80 | Quarantine is on by default: what the app removes from other drives (Cleanup, My Clutter, app leftovers) goes to `S:\Quarantine\<date>\<batch>\` with a manifest, moved by copy, size check, then delete of the original. It is used only if the disposable drive is present and Windows reports its disk healthy; otherwise the Recycle Bin. Items already on S: go to S:'s Recycle Bin. "Delete for good" in Cleanup still wins; My Clutter and leftovers never delete for good. | Spec: frees space at once, 30-day safety net; refuse a failing drive. |
| 81 | A quarantine batch can be put back (from the Drive Organizer or My Activity); nothing is overwritten: an item whose name is taken stays in quarantine. Purging batches older than 30 days happens only after the user answered yes once ("purge automatically?"); then at each app start. | Spec: ask the first time. |
| 82 | `S:\Scratch` is created when the Drive Organizer first lists it; items older than 14 days are listed and can be moved to S:'s Recycle Bin. | Spec. |
| 83 | The ongoing guard (watching libraries and the profile for large new items, with a tray notification) needs the app to run in the background, so it comes with the tray in Phase 4. The page links to Settings > "Where new content is saved" now. | Phase 4 brings the tray and background run. |
| 84 | The real dry-run plan for this PC (2026-11-12): 14 games, all on the right drive; one item to move (npm cache, 1.1 GB, C: → `X:\Caches\npm`); Football Manager 26 on X: as information only; nothing on S:. Nothing was moved during development; migrations were tested on temporary folders only (copy-verify, resume, junctions, existing target, cross-drive move C: → G:). | Spec: test on a temporary folder first, show the real plan before running anything. |

## Phase 4: Privacy & Tweaks, Toolbox, tray, scheduler, admin helper (2026-11-12)

| # | Decision | Why |
|---|---|---|
| 85 | The elevated helper is the same program (`smd.exe --helper <pipe> <app pid>`), started with `ShellExecuteExW` and the `runas` verb when an admin action needs it. It handles only the typed operations of `smd_win::helper::Op`: restore point, turn on System Protection, admin cleanup scan and removal, machine-wide startup items, machine-wide part of a catalog tweak, SMART counters, sensors with admin rights. No operation takes a command, a program path or a registry path. | Spec: least privilege, allow-listed typed operations, one installer. |
| 86 | Transport: the app creates `\\.\pipe\smd-helper-<pid>-<128-bit random>` with `FILE_FLAG_FIRST_PIPE_INSTANCE` and `PIPE_REJECT_REMOTE_CLIENTS`. The helper connects with `SECURITY_IDENTIFICATION` (the pipe owner can never impersonate the elevated token) and checks that the pipe server's process id is the app's and that its program file is its own. JSON lines, one request at a time. | A squatted pipe name or a fake server gets nothing. |
| 87 | Each operation re-checks its input inside the helper: cleanup only removes paths its own new scan of an `admin` rule finds (then `safety::check_removal` again); tweaks are looked up by id in the built-in `tweaks.json`, and an undo is replayed only if every value and service in it is declared by that tweak; startup items are looked up by id in a fresh listing. | Never act on what the UI sends. |
| 88 | One UAC prompt per working session, not per click: the helper stays up until the app closes the pipe or after 10 minutes without a request. The Tweaks page shows when admin rights are on and has "Turn off now". A helper that timed out is started again (new prompt) on the next admin action. | Spec says "UAC per batch"; a batch often spans a scan and its cleanup. |
| 89 | Admin cleanup: the categories (Windows temp, update cache, Delivery Optimization, system error reports, memory dumps) are listed by the normal scan, then "Check Windows files too" rescans them in the helper. They can be ticked only after that. The helper moves them to the system drive's Recycle Bin, never to the S: quarantine (restoring there would need admin again). They are not part of the cleanup's in-app undo. | Reversible, but honest about what the undo button covers. |
| 90 | Tweaks are declarative (`rules/tweaks.json`): registry values (`HKCU\Software\...` or `HKLM\SOFTWARE\Policies\...` only, checked when the catalog loads), service start types, or one Store app. The state shown is read live (registry, `Start` value, `Get-AppxPackage`). No registry cleaner, no "performance" tweaks. | Spec: apply, undo, detect per tweak; no snake oil. |
| 91 | Undo data per tweak (`tweaks-undo.json`): each old value with its raw type, whether it existed, and the highest key the tweak created (removed again only if empty). Your-account values are changed by the app; machine values and services by the helper (an elevated process of another admin account must never write someone else's HKCU). The oldest record wins, so undo goes back to before SMD touched it. | Exact undo. |
| 92 | Services are changed with `sc.exe config <name> start= ...` (started directly, never through `cmd`); delayed automatic start is restored as such. | Official tool, no SCM handle juggling. |
| 93 | Store apps are removed for the current account only (`Remove-AppxPackage`, no provisioned-package removal, no admin). The undo is "Reinstall", which opens the Microsoft Store page (`ms-windows-store://pdp/?PFN=...`). Xbox components, Store, Photos, Notepad, Calculator and Quick Assist are not in the list; Phone Link is marked "use caution". | Reversible without keeping copies of system packages. |
| 94 | A restore point is made before any batch with machine-wide changes (`Checkpoint-Computer` in the helper). Windows makes at most one per 24 hours: when it skips, the page says which earlier point covers the batch. If System Protection is off or the point fails, nothing is changed until the user picks "Turn on System Protection and go on" or "Go on without". Your-account-only batches make no restore point (each change has its own undo, and a restore point would mean a UAC prompt). | Spec: restore point before system batches, handle and report the 24 h limit. |
| 95 | Toolbox catalog in `rules/toolbox.json`; IDs checked with `winget show` (Krokiet is `qarmin.krokiet`, UniGetUI moved to `Devolutions.UniGetUI`). Installed state comes from `winget export` (about 20 s, cached for the session; written to the temp folder because winget's writes under AppData are redirected). Install and update run `winget install/upgrade --exact --source winget --silent`. "Open" uses the Start menu entry (`Get-StartApps`) or the program winget unpacked for portable tools. PawnIO is in the list because LibreHardwareMonitor needs it for CPU temperatures. | Spec; the license of each tool is shown on its card. |
| 96 | Tray: a tray icon with a menu (Open, Run Smart Care, Quit) and, on left click, a 340×470 popover window (`#/tray`) with CPU, memory, disk and network sparklines (sampled every second only while it is open), CPU temperature when a sensor helper runs, free space on the system drive, the last Smart Care score, and Smart Care / Empty Recycle Bin (asks again) / Open. | Spec. |
| 97 | Closing the window quits, unless a task is running (the window hides, a notification says when the task ends) or "Keep running in the tray" is on (off by default). | Least surprise; spec asks to keep running during a scan. |
| 98 | Scheduled Smart Care: a Task Scheduler task "Scrub My Disks Smart Care" for the current account (limited rights, interactive, runs when available, 30 min limit) runs `smd.exe --smart-care --silent`: scan only, a notification with the score, then the app exits.
